# Project Management Plan — FORMA Restaurant

## 1. Project Goal

The goal is to plan, design, develop, and test a minimalistic restaurant website called FORMA.

## 2. Project Scope

The project includes:
- Homepage
- Restaurant description
- Menu section
- Photo gallery
- Reservation request form
- Contact information and opening hours
- Responsive layout for desktop and mobile devices
- Project documentation and testing

The project does not include online payments or a real restaurant booking database.

## 3. Project Schedule

| Stage | Planned Dates | Expected Result |
|---|---|---|
| 1. Project preparation | 19–22 October 2026 | Project description and team roles |
| 2. Requirements and structure | 23–27 October 2026 | Requirements and website structure |
| 3. Design and prototype | 28–31 October 2026 | Website visual concept |
| 4. Website development | 1–8 November 2026 | Main website sections |
| 5. Functionality and responsive layout | 9–14 November 2026 | Interactive elements and mobile layout |
| 6. Testing and final documentation | 15–20 November 2026 | Tested website and final report |

These dates are preliminary and must be confirmed against the course deadline.

## 4. Team Organization

The project has three student participants.

- Project Manager / Analyst: coordinates tasks, monitors deadlines, and maintains documentation.
- UI/UX Designer / Frontend Developer: prepares the visual concept and implements the page layout.
- Developer / Tester: helps implement functionality, checks the website, and reports defects.

The team will confirm the names and final responsibilities of each participant.

## 5. Tools and Resources

- GitHub — source control, tasks, milestones, and pull requests.
- HTML — website structure.
- CSS — visual design and responsive layout.
- JavaScript — interactive elements and form validation.
- Web browser — testing and preview.
- diagrams.net — project diagrams and website structure.

The planned tools are free to use for this student project.

## 6. Risk Management

| Risk | Impact | Mitigation |
|---|---|---|
| Tasks are completed late | High | Divide work into small tasks and check progress regularly |
| Team members have limited experience | Medium | Use simple technologies and share instructions |
| Website does not display correctly on mobile | Medium | Test different screen sizes |
| Errors are found near the deadline | High | Test each section during development |
| Team communication is delayed | Medium | Record tasks and blockers in GitHub |

## 7. Communication and Monitoring

The team will communicate about progress, assign tasks, set deadlines, and report blockers. GitHub Issues will be used to record work items. Milestones will group tasks by project stage. Changes can be reviewed using pull requests.

## 8. Quality Criteria

- All planned sections are present.
- Navigation links work correctly.
- The reservation form validates required fields.
- The layout works on desktop and mobile screens.
- Contact information and opening hours are clearly visible.
- No major visual or functional defects remain after testing.

## 9. Project Deliverables

- Project description
- Project management plan
- Website structure and design prototype
- Website source files
- Test checklist and test results
- Final project documentation
