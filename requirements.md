
# Software Requirements — FORMA Restaurant

## 1. Purpose

This document describes the requirements for the FORMA Restaurant & Bistro website prototype. The project is educational and represents a fictional restaurant in Bălți, Republic of Moldova.

## 2. Project Scope

The website presents information about the fictional restaurant and demonstrates a reservation form. It is a static front-end prototype built with HTML, CSS, and JavaScript.

The prototype does not send reservation requests to a real restaurant, save personal information in a database, provide online payments, or use a server-side booking system.

## 3. Functional Requirements

- **FR-01 — Main page:** The website displays the FORMA brand, an introductory section, and navigation to the main content sections.
- **FR-02 — Restaurant information:** Visitors can read about the restaurant and its concept.
- **FR-03 — Menu:** The website displays sample dishes, descriptions, photographs, and illustrative prices.
- **FR-04 — Gallery:** The website includes photographs representing the restaurant atmosphere and food.
- **FR-05 — Reservation form:** The website provides a demonstration form with fields for name, phone number, date, time, number of guests, and optional wishes.
- **FR-06 — Form validation:** JavaScript checks required fields and provides feedback after submission. The feedback explains that the form is only a demonstration.
- **FR-07 — Contacts:** The website displays contact information and opening hours, identifying fictional or illustrative information clearly.
- **FR-08 — Language selection:** Visitors can switch the interface between Russian, Romanian, and English where translations are provided.
- **FR-09 — Navigation:** Navigation links and buttons lead to the relevant sections of the website.
- **FR-10 — Mobile navigation:** The website provides a compact navigation control for smaller screens.

## 4. Non-Functional Requirements

- **NFR-01 — Responsive layout:** Content adapts to desktop and mobile screen sizes.
- **NFR-02 — Usability:** Navigation labels, buttons, and form fields are understandable and easy to locate.
- **NFR-03 — Visual consistency:** The website uses consistent typography, colors, spacing, and imagery.
- **NFR-04 — Browser compatibility:** The website runs in a modern web browser without requiring installation.
- **NFR-05 — Maintainability:** HTML, CSS, and JavaScript are stored in separate files.
- **NFR-06 — Transparency:** The interface identifies the restaurant concept, menu prices, and reservation process as illustrative rather than a live booking service.

## 5. Constraints and Assumptions

- The restaurant and its owner are fictional and created for educational purposes.
- The project is a front-end prototype; it has no backend or database.
- Menu items and prices are examples.
- Contact details and opening hours are not verified real business information.
- Photographs and web fonts may be loaded from external services and require an internet connection.
- Translations may be reviewed and improved during testing.

## 6. Acceptance Criteria

The prototype is ready for educational demonstration when:

1. The main sections are accessible through navigation.
2. Menu cards and gallery images display correctly.
3. The language selector changes supported interface text.
4. The reservation form checks required fields and provides clear feedback.
5. The confirmation does not claim that a real booking has been made.
6. The layout remains usable on desktop and mobile screens.
7. The site and documentation identify the project as a fictional educational prototype.

## 7. Verification

Requirements will be checked through manual testing in a web browser. Test results and screenshots will be recorded in the final project report after the checks are performed.
